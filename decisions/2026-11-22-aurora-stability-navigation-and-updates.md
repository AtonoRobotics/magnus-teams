# Aurora stability, complete left-rail navigation, responsive top header, and update flow

## Choice

Fix seven live desktop app issues reported after the Aurora layout refinement:

1. **Page close button (`desktop/ui/aurora-pages.js`)**: Record `conversation` only when `#main` shows a conversation *and* `location.hash` is a conversation route (`#/chat/...`, `#/home`, or empty). Fall back to `#/chat/new` if `conversation` is missing or matches `location.hash`. Previously, `hashchange` ran `place()` before async pages (Explore, Teams, Admin) replaced `#main`, overwriting `conversation` with `#/explore` and turning the `×` button into a no-op.
2. **Explore re-render loop (`desktop/ui/aurora.js`, `desktop/ui/discover.js`)**: Exclude `.aurora-page-bar` from `aurora.js`'s `#main > *:not(section.conv):not(.aurora-page-bar)` `viewKey` query so prepending the close bar does not ping-pong entrance animations. In `discover.js`, update `#explore-ideas`, scan state, and `.explore-grid` in place when `.explore-page` is already mounted and keep `main._html` synchronized after `drawGridOnly()` so background `refresh()` polls never wipe Explore.
3. **Bento card high-frequency flicker (`desktop/ui/aurora-stage.js`)**: Cancel any prior `"stage-slide"` animation on a tile before measuring its destination rect in `slide()`, tag new slide animations with `id = "stage-slide"`, and restrict the bento `ResizeObserver` (`sized`) to actual width changes while skipping active `"stage-grow"` height animations.
4. **Superimposed stale overlays and modal freeze (`desktop/ui/aurora.js`, `desktop/ui/aurora-explore.js`, `desktop/ui/aurora-rail.js`)**: Track `detailHash` on `noteDetailRect()`, skip spawning `.aurora-detail-ghost` across route changes, and clear any ghosts on `hashchange`. Clear `before` and `.explore-leaving` nodes on `hashchange` in `aurora-explore.js` with a fallback timeout (`EXPLORE_LEAVE_FALLBACK_MS`). Close `#navigation-drawer` on `hashchange` in `aurora-rail.js` so an open modal drawer can never freeze a new route, and keep an open Aurora slide-out drawer alive across `Workspace.update()` while `m.nav === "compact"`.
5. **Updates requiring repeated Install/password prompts and manual restart (`desktop/ui/admin-ops.js`, `desktop/ui/admin.js`, `desktop/ui/app.js`, `desktop/ui/server.js`, `desktop/src-tauri/src/update.rs`)**: Disable `[data-ops-install]` / `[data-ops-rollback]` immediately with an in-flight guard and persist pending progress across repaints until the server restarts onto the new version; poll `Server.version({ background: true })` during restart and also track `App.serverVersion` during normal `refresh()`, calling `refreshUpdate(true)` automatically as soon as the server version advances so `"Restart to update"` appears without restarting Magnus. Disable the `Confirm` button during `stepUp()` and `[data-act=restart-update]` buttons during `restartToUpdate()`, and restore `ups.ready` in Rust if `update.install(&bytes)` returns an error.
6. **Complete left-rail navigation (`desktop/ui/app.js`, `desktop/ui/layout.css`, `desktop/ui/aurora-rail.js`)**: Add `Teams` (`#/teams`) and `Apps` (`#/library`) as primary-nav items on the left rail between `Explore` and `Settings` (preserving `desktop/tests/aurora-rail.mjs` ordering and exclusions), define `UI.team` in `app.js`, and clarify the rail sidebar button tooltip (`Sidebar & conversations (Ctrl+B)`).
7. **Responsive conversation top header (`desktop/ui/aurora-stage.css`, `desktop/ui/chat.css`)**: Mark Aurora's `section.conv` as `container-type: inline-size; container-name: aurora-conv` and use `@container aurora-conv` breakpoints (`680px` and `500px`) instead of only a `760px` viewport media query so `.computer-chip-words` collapses and `.conv-head` wraps cleanly whenever the conversation column narrows in split view or smaller desktop windows, keeping `Your computer` and `Trash` always visible.

## Reason

Each failure stemmed from an asynchronous boundary or viewport-vs-container mismatch: async page renders racing `hashchange`, `ResizeObserver` firing during height animations, `202 Accepted` update responses returning before `Ev::UpdateStarted` with no pending UI lock or post-restart desktop check, and viewport-only header rules failing inside narrow split-view columns.

## Verification

- Fast-tier checks: `desktop/tests/aurora-stability-check.mjs`, expanded `desktop/tests/admin-ops-check.mjs`, and all existing `desktop/tests/*-check.mjs` (including `stylesheet-check.mjs`, `globals-check.mjs`, `theme-check.mjs`, `explore-ideas-check.mjs`, `server-check.mjs`), plus `ci/ratchet.sh size` and `cargo fmt --all --check`.
- End-to-end headless Chromium verification across desktop split widths (800px–1280px, pinned & rail) and mobile (390px) confirming zero clipped header controls, zero Explore wipes on background refresh, working `×` close back to the conversation, zero stale ghosts/frozen drawers, single step-up + disabled Install + automatic `updateLook` on server restart, and complete left-rail navigation.
