# Accounts live in Postgres (2026-11-08)

- The accounts store moved from `accounts/*.json` to nine `account_*` tables made by `migrate`, per the spec's People section (owner, 2026-11-07: postgres) (#466). Reason: the JSON files rode no backup, so once embedded auth is the only auth a restore would bring back everything except the ability to sign in; in Postgres the tables ride a table-scoped dump, and transactions plus an advisory lock retire the CLI-vs-server write race the slices accepted.
- Correction to the issue's assumption: the tables do NOT ride the existing dump — `dump_databases` covers only `[backup] databases`, while the main database is backed up by logical log replay, which must never hold account material (invariant 2). So backups carry an explicit `accounts` table dump, restored data-only into the migrated tables (grants untouched); `check()` validates it and scrub round-trips it.
- `Accounts` keeps its behavior and sheds its files: async methods on a lazy client (the `knowledge::Index` pattern), single-use invites/TOTP steps/compare-and-set by SQL (advisory lock for the read-check-write switches), sessions resolved against the store on every call — which closes #469 (removal/disable invalidates across processes permanently; re-enabling restores sign-in, never ended sessions — the old cross-handle test pinned the resurrection the P1 forbids).
- The directory (`is_local`/`local_person`/`local_people`) stays sync behind a 30s cache because `Kernel::person` is sync; the sign-in routing decision and session issue read fresh (`is_local_fresh`, `refresh_people`), after the e2e proved a CLI-added person otherwise misses routing on a warm server. Enforcement (status/session/password) is always fresh, so cache lag never admits anyone.
- `magnus migrate` imports the JSON files once (idempotent, expired rows left behind) for the strix-alpha cutover; the CLI commands use `database.url`. Cutover edge, recorded: a backup taken before this lands holds no accounts dump, so after Keycloak is gone only post-cutover backups restore sign-in — take a fresh backup at cutover.
- Tests: 17 unit tests on fresh TestDb databases (parity conversions + `removal_elsewhere_ends_sessions_and_readding_resurrects_nothing` for #469 + `migrate_imports_the_json_files_once`); `local_people` e2e unchanged (parity through real CLI+API); new backup e2e proves backup→disaster→restore keeps a local admin signing in. Full lib 144/144; backup 4/4, admin/people/cold-start suites green.
