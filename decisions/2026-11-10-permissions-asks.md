# Only the four asks of spec rev 140, from one place, with a card the server builds

Spec rev 140 ("Permissions and tasks") says only four things reach a person as an ask, and the person sees only a server-written card. The owner asked for a rebuild to it that deletes the old paths instead of layering on them. This records what changed, what was deleted and why.

**One module asks.** `crates/magnus/src/asks.rs` is the only code that makes an approval item (`raise`), and the only one that decides whether the person's own answer already covers an action (`person_cover`). It names the four asks as `asks::Reason`:

1. **Outside what was asked** (`outside_request`). Auto Review judges a boundary action. When it asks, or cannot answer, or allows without the owner's delegation, this is the ask. A send reviewer's flag is the same case. Enforced in `Kernel::settle`. As before, a grant or schedule the person set up answers for them on an action that sends nothing out, without Auto Review; a send it covers is still judged.
2. **A payment** (`payment`), every time. `payment_ask` in the boundary's policy stage. No rule answers it and Allow covers one action.
3. **Private data to a new destination after untrusted input** (`new_destination`), the Rule of Two floor, unless a rule covers it. Recipients the person named pass, and so does a destination the person allowed once before (`asks::remembered`). A web lookup's host is its destination. It is never Auto Review's call alone (invariant 4): the floor runs before Auto Review and Auto Review never sees it. Allow covers one action, and there is no Allow always.
4. **The person's own ask-first rule** (`ask_first`): `rule_effects::person_rules` and, for the person's own computer, `local::local_gate`.

A unit test (`asks_tests::no_ask_outside_the_four_can_be_produced`) maps every rule string the kernel asks with to one of the four, and fails if any other file in the kernel makes an approval item or names one of the deleted asks.

**Deleted.** Each of these asked the person something rev 140 does not:
- the contract-change request to the person (a frozen contract now refuses the change and tells the agent to finish against its criteria or fail; main's 8579661 took the same course);
- the criteria review: a criterion no check, verifier or reviewer could confirm no longer suspends the task for the person to accept or reject. Rev 140: "That checking is internal: the person sees the result, not criteria or contracts." The task completes, the agent is told which criteria no check confirmed ("Not confirmed by any check: c1"), and that stays in the run's log for the developer view. Review items already in a database keep their reader and card;
- the per-task new-source ask of the computer's sources tool (it grants the host to the task);
- the audience ask (`kernel:audience`) for private data to a wider audience without untrusted input: Auto Review judges it as any other boundary action;
- the web-lookups-after-private-data ask (`kernel:web_lookups`): a lookup asks only as case 3, after untrusted input too;
- the local-change ask a policy Ask raised on the person's computer (`kernel:local_change`): a policy's Ask is no longer an ask, only its Deny stands;
- the unknown-outcome ask after a write that may have reached an app that cannot deduplicate (cut off by a restart, or answered with something unreadable). It is not sent again, the agent is told to check, and the person gets a notice on the task (`asks::outcome_unknown`). The agent's identical retry is refused as a hard denial (`rules::hard_denial`), so the old ask's protection stays without asking;
- the web-lookups ask after an upload (the owner's decision of 2026-10-29): rev 140 makes a lookup ask only as case 3, after untrusted input. The library tests now check that one ask per new host, remembered after;
- the approval-for-an-hour ("window") and standing scopes (approvals written with them before are still read), named approvers answering a team thread's ask (only the asker answers there), Auto Review's routing table (`route`, `clear_ask`, `review_permitted`), the old approval and reviewer stages of the boundary, and the unattended-expiry setting.

The Never-allowed denials, payments, the floor, taint and the reviewer's block are unchanged. Reads and everything inside the computer pass without review (`asks::is_boundary`).

**What an update leaves open.** At startup, before any run is driven, items still open under the retired asks are put in their current form (`legacy_items`): a criteria review completes its run with the criteria unconfirmed (the agent's own summary and view stand), a contract change is refused and its run goes on against the frozen criteria, and an approval whose rule is not one of the four is withdrawn, the agent told the action was not done and to do it again if it is still needed, so the boundary judges it as it would now. Each is marked "superseded", so the person's inbox holds only the four asks after the update, not only after the next run. The reviews of tool descriptions were already retired as they are read (`consent::RETIRED_KINDS`). `tests/scratch/tests/retired_asks.rs` writes each kind into the log as an earlier release left it and checks the inbox is clean after a restart.

**The card.** The inbox renders an approval with `ask`: one sentence the server wrote from the action's fields (`asks::sentence`), the destinations, the offered answers, the scope Allow gives, and the conversation it belongs in. The details keep the exact content (one tap away in the app) and lose the rule, the reason, the taint and Auto Review's or the reviewer's words (`asks::without_reasoning`). The agent never writes or sees it: the model is told only the outcome.
- **Allow** covers the rest of the task for the same kind of ask and the same destinations (`scope: task`); for a payment and case 3, one action (`scope: once`). The approval event gets an optional `destinations` field, defaulting to none, so earlier approvals read as before (an event kind is never edited).
- **Allow always** is offered on case 1 only, to the person whose work it is, when the action has a destination. It saves a narrow rule through `rules::compile`, accepted at once, which counts as the person's answer ahead of Auto Review next time. A rule never answers a payment or an ask-first rule.
- **Don't allow** stops that action. The agent is told to carry on with what does not depend on it (`asks::declined`).
- In a team thread only the asker can answer.
- A sub-agent holds an Allow given to any run above it, and a chat turn one given in its conversation (decisions/2026-11-10-sub-agents-carry-parent-authority.md).

**Unwatched work.** On a schedule or in the background, an ask waits `UNWATCHED_ASK_WAIT_MINUTES` (30). Then a message stays a draft and the item is closed; anything else keeps waiting for the person while the run is told to carry on with what does not depend on it, and is told again if the person allows it later.

**What only developers see.** The rule, the reason, the taint and the reviewer's words are on `/v1/dev/runs/{id}` (each ask's `reasoning`, each action's decisions with reason and rule) and drawn by `dev.js`, not on the inbox, the task view's decisions or toasts. Scratch tests that read them now read them as a developer (`tests/scratch/src/dev_view.rs`).

**Tests changed with it.** The scratch Auto Review player (`tests/scratch/src/checks.rs`) now judges what was asked, as rev 140 has Auto Review do: every action the tests' person asks for is within the ask, unless its content carries `OUTSIDE_THE_ASK`. It used to allow only what a policy permit, rule or grant covered, which no longer decides. Tests of scopes that can no longer be given (standing, window, and their role and erasure cases) are removed; the contract-change tests now check the change is refused and never put to the person; the reviewer, Rule of Two and taint assertions read the rule and reason from the developer view. `tests/scratch/tests/asks.rs` covers the card, Allow, Allow always and Don't allow end to end, and that the agent never sees the card. Tests that waited on a review card now wait for the task to complete; those that needed something to answer (trash, layout, volume) answer a question instead; the two built on a rejected review (a crash through an accepted review, and two memory passes on one run, which only a rejected review produced) are removed. The browser scripts no longer accept a review after Allow. The contract-change hunk of `docs/proposals/invariant-tests-tightened.patch` is obsolete.

**Invariants.** `inv4_taint::private_data_sent_to_a_wider_audience_asks` encodes the deleted audience ask. It passes today only because the scripted model cannot answer Auto Review. `decisions/2026-11-10-permissions-asks-invariants.patch` replaces it with the same post made after untrusted input, which must ask as case 3 with neither a task-wide Allow nor Allow always. `inv7_verify::a_criterion_without_a_check_goes_to_the_person_for_review` puts criteria to the person; the same patch replaces it with a test that the task completes, nothing is put to the person, and the criterion is recorded as unconfirmed. It needs the owner's `git apply`. `inv3_event_log::crash_against_an_app_without_idempotency_asks_instead_of_resending` still passes unchanged: the person's notice is the open inbox item it waits for, and nothing is sent again.
