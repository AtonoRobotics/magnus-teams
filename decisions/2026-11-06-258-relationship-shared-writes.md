# What a run writes for others carries its person's memory, so it is theirs (2026-11-06)

- Every run of a person carries their relationship context in its system context (`person_context`: notes, recent messages and task results, reactions, open disagreements, the suggestion ledger, grants, commitments). Whatever it files to the knowledge base or writes into an org document may carry it, and that context is labelled nowhere in the run (`private`, `private_from`), so before this both were readable by everyone: Carol's "file what we know about Acme" could put "Carol is wary of Acme" in an entry Bob's search returns. The behavior spec: "One user's relationship memory never surfaces to another user."
- Now, when that context is not empty (`Kernel::carries_person`), what the run writes for others is the person's, as private content it read is: a knowledge entry it files (`knowledge_add`) is readable by the person only (a `person:` clause in its readers, so a value extracted from it is too), and an org document it writes (`bundle_write`) names `private:memory` among its sources, so only its writer sees it (K2). The person's own documents and memory are unchanged. Reason: the rule already used for a run that read private content; a model can paraphrase what it knows of the person, so the kernel cannot tell from the text whether it did. Tests: `knowledge.rs` `what_a_run_files_with_its_persons_memory_in_context_is_theirs_alone`, `org_context_bundle.rs` `an_org_document_written_with_its_persons_memory_in_context_is_theirs_alone` (both fail without it: Bob reads it).
- The cost: a person who has used Magnus at all has context, so research their runs file is no longer shared with colleagues by itself. Shared company knowledge comes from people (`POST /v1/knowledge`, readable by groups or everyone), from admins (the console's documents), and from endorsement; a way for the person to share an entry or document filed for them only, after reading it (their say), is a follow-up issue. Not here: sends to other people, which already go through the send gate and the person's approvals; a run's taint (`private`) is unchanged, so relationship notes and the Rule of Two behave as before.
