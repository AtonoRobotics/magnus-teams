# Disagreement outcomes record from any run and tell the person at once (2026-11-07)

- `disagreement outcome` no longer refuses runs that read outside content; such a run's outcome is a fixed value (`worked`, `failed`, `unclear`), so that content writes no free text into the person's log (#260). Reason: an outcome is nearly always learned from outside content (a reply count, app data), so the old refusal left disagreements open in every later run's context. A run that read nothing outside the conversation still says it in its own words, as the existing outcome test pins. `record` stays refused for tainted runs: its words enter every later run. Tests: `an_outcome_is_recorded_from_a_run_that_read_outside_content_but_only_as_a_fixed_value` (fails without: worked refused with the blanket taint message).
- Recording an outcome tells the person at once with a message item, honestly whichever way it went: worked says they were right, failed says it didn't work out without gloating, unclear says it is still unclear; a clean run's own words are quoted (`outcome_report`). Reason: nothing asked Magnus to tell the person, and a settled disagreement leaves the context at once, so outcomes were never reported. The report is the kernel's, not the model's, so it is guaranteed and toneless. Tests: `when_an_outcome_is_recorded_the_person_is_told_honestly_either_way` (fails without: the inbox stays empty), `an_outcome_report_is_honest_either_way`.
- The report item is the person's alone: the run inspector and raw log redact its summary for another developer, keyed on the item's `disagreement` marker, as disagreement calls already are (#257). Reason: the report quotes the record's words. Test: `a_developer_reading_another_persons_run_sees_no_note_or_disagreement_words` now settles too (fails without the redaction: the `inbox_message` text carries the canaries).
