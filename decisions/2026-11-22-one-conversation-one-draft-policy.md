# One conversation for personal and shared-project chat, with one draft policy (2026-11-22)

## Choice
- Personal chat and a shared project's chat open through one conversation, `Conversation` in `desktop/ui/chat-view.js`, beside the one chat view. `Conversation.open(root, spec)` loads the model picker, mounts the chat view, draws the composer and wires it to the conversation's draft. Both `chatLayout` (app.js) and `TeamChat.mount` (team-chat.js) call it. `Conversation.draft(place)` returns the one draft for a personal thread, a project's new conversation, or a shared conversation or thread. `Conversation.track` keeps the composer's Stop and Steer state from a draw. `Conversation.stop` stops running work. Each kind of chat now supplies only its source: personal-chat.js, or team-chat.js and team-conversation.js for a shared project. A source says where items come from, where a message, a file and each control go, and what only several people have: member names, @Magnus mentions, whispers, reactions, threads, release and steer of mission lanes (team-rooms.js), and the "Answer:" prefix of a clean-room share (shared-canvas.js).
- A shared project's draft follows the personal policy (#544, decisions/2026-11-08-544-session-drafts.md). It is kept in memory for the session, nothing is written to the device, signing out forgets it, and another person signing in on the same computer starts with none. The shared-project draft store `TeamDrafts` (localStorage `team-draft:<ws>:<channel>:<thread>`, not keyed by person, kept through sign-out) is removed, along with the composer's `keep` hook that wrote to it. `MessageDrafts` moves from app.js into chat-view.js. When someone signs in or out, it deletes any `team-draft:` keys an earlier version left on the device.
- Removed as duplicates: the second mount sequence, the second Stop handler, the second running-work bookkeeping, and the second reading of the Start shared work form (now `TeamRooms.missionAsk`, used by team-panel.js and shared-canvas.js). Every route call stays where it was: mission list and create, releaseLane, steerLane, the whisper post, shareWhisper, shareAnswer, the whispers list, capabilities, addRoutine.
- No new script file. The server serves the web UI from a fixed list in `crates/magnus/src/ui/assets.rs`, and its test requires every script index.html loads to be on that list. This change does not touch Rust, so the conversation code goes into chat-view.js and team-chat.js stays. A later change can split `Conversation` into its own file by adding one line to that list.

## Reason
The owner's rule (decisions/2026-11-22-unified-shared-projects-and-conversations.md and decisions/2026-11-22-pure-peer-collaboration-personal-agents.md) is that a shared project's chat is the personal chat with many users: one UI, and the same backend unless there is a real need. The two chats had opposite draft policies. A shared-project draft stayed on the device after sign-out, and the next person to sign in on that computer saw it, which breaks #544. With one conversation there is one policy, and a fix to one chat applies to both. One example: a Stop pressed before the work had an id now stops that work in a shared conversation too, as it already did in personal chat.

## Test
`desktop/tests/shared-draft-check.mjs` opens a shared conversation through `TeamChat.mount` with the real chat view and composer on a fake page, then types into it. The test fails on the previous code: the message was written to localStorage, came back after sign-out, and was shown to the next person on the device. It passes now. `draft-check.mjs` reads the drafts from chat-view.js.
