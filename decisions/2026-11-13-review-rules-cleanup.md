# Kernel code brought in line with the AGENTS.md rules (durations, unwrap and expect, the environment)

**Choice.** In the kernel (`crates/magnus/src`, outside `run/agent_loop.rs`, `api.rs`, `sandbox.rs`, `generated.rs` and `computer/`, which another change covers):

- Every bare `Duration::from_secs(N)` / `from_millis(N)` outside tests is a named constant near the top of its file (`browser`, `run/mod`, `oidc`, `devices`, `conformance`, `apps`, `web`, `connectors`, `kernel`, `ops_admin`, `log`, `tls`, `brokered`, `adapters`, `update`, `trash`, `proactive`). The constants are `Duration`s, which carry their unit, as the existing ones (`DRAIN`, `BOOT_WAIT`) do; a plain number keeps its unit in its name (`MARK_RETRY_STEP_MS`, `BACKOFF_FIRST_SECS`, `PLAIN_HEAD_MOST_BYTES`). The debug-only sweep gate keeps its two constants inside the function, so release builds have no unused ones.
- A poisoned `std::sync::Mutex` is taken as it is (`.lock().unwrap_or_else(|e| e.into_inner())`, the pattern in `payments/routes.rs`) rather than panicking: `oidc`, `devices`, `browser`, `run/mod`, `spawn`, `connectors`, `adapters`, `kernel`, `brokered`.
- `expect()` outside tests became a fallible path: `Web::new` and `Mcp::new` return the client builder's error to startup; the connectors' provider client falls back to the default client (as `push_subs::http_or_default` already does) and the no-redirects probe returns its error, which counts as "not refused"; the async runtime that cannot start ends `magnus` with exit 1 and the reason; the spawner thread that cannot start makes each later spawn fail with "spawner stopped"; the voice's piped stdin is an error, not a panic; the Slack hand-off address is built with a form serializer instead of parsing a constant URL; a log record's content bytes come from `Value::to_string`, the same compact JSON.
- Compiled-in assets whose parse a test checks no longer panic if broken: the Cedar schema halves (`policy_admin`) are parsed once into a `Result`, and a broken one refuses every policy with the reason; a catalog manifest that does not parse is logged and left out (the test now asserts every source parsed); broken registrations or tool descriptions are logged and read as empty. Tests were added or tightened so each of these still fails the build when the asset breaks.
- `PATH` and `HOME`, which the browser sidecar and the model adapters inherit, are read once with the config (`Config::host`, a `spawn::HostEnv`) and passed to `Browser::new` and `Adapters::new`, instead of being read from the environment at each launch.

`ci/clippy-baseline` falls from 694 to 617.

**Reason.** AGENTS.md: "A duration or limit is a named constant with its unit in the name"; "No `unwrap()` or `expect()` outside tests ... the count may only fall"; "Config is typed, validated at startup and passed in. Logic never reads the environment." Behaviour on every working path is unchanged: the same values, the same clients, the same environment for children; only the paths that used to panic now return an error or carry on.
