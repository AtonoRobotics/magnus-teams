# Digest wakes for new items in connected apps (#369)

Split from #237: no connector push primitive exists, so this ships
the digest option — watched reads diff their answers, and new ids
wake a review. Scheduled polling (for items never read again) is
#406; push hooks need connector cooperation that does not exist.

Each connector lists watched reads: the remote tool, a JSON pointer
to its answer's array (`""` for the answer itself), and each item's
stable id field. The boundary calls `note_watched` after a watched
answer (only watched tools pay for the clone). The first sighting
seeds the baseline silently via `Ev::WatchedSeen`; later sightings
diff, and new ids wake one review naming the count. The baseline
advances only when the wake starts a review (`review_wake` and
`start_review` now report that), so a wake dropped for an active
review retries on the next read instead of losing the items.

The reason carries the count only, never item content: the review
pulls the items itself through the boundary, tainting normally and
honoring the loop's `act` governance (#368). No per-item wake
marks: the baseline is the dedup. Baselines cap at five thousand
ids per watch.
