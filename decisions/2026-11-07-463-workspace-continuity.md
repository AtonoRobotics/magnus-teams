# Durable workspace conversation continuity (2026-11-07, #463)

- Keep one versioned atomic message journal per appliance/person, with locally generated identities for independent unsent conversations. Flush debounced text/reference/selection changes before navigation where possible; report only successful device writes as saved. Preserve memory on write failures and same-person session recovery; explicit sign-out clears scoped message drafts.
- Separate immutable submitted snapshots from the editable current draft at dispatch. An accepted response must provide thread/task identity before clearing its snapshot; later typing and attachments survive. A definite authoritative rejection restores the submitted content separately from newer edits. The current chat API provides no stable send-operation identifier, lookup or deduplication contract, so a lost response uses UX-08's explicit unconfirmed/no-safe-retry branch. Never match by text/time or automatically resend it.
- Persist only attachment metadata and successful uploaded references. File objects stay in memory. Uploads continue across view navigation; detached slots cannot reattach after late completion. A restart without authoritative upload association marks it interrupted and requests re-selection; missing references remain removable without losing text or deleting shared files.
- Keep visible entry/relative-offset anchors, including semantic nodes inside composed frames; follow only within 80px of the prior bottom or explicit Jump to latest. Polling timestamps and focused actions do not force latest. Observe size changes rather than guessing content completion from time.
- Deliberate work opening focuses its heading, explicit closing restores the opener or conversation heading, and work-object changes create history entries. Status redraws create none. Local discard is an explicitly labeled local action and adds no approval step; it does not cancel or confirm submitted work.
