# One owner for the knowledge index

The `public.knowledge` table keeps each entry's full text for search. Seven call sites kept it up to date, each its own way: the trash returned an error after the trash was already recorded, a share ignored a failure, adding said "indexed when the server next starts", and nothing retried until the next start. Removing content never touched the index, so a trashed or removed entry stayed searchable, with its text, until a restart.

Now `knowledge_index` owns it. Every write goes through `Kernel::emit_all`, which hands the events to the index: each knowledge add, share and endorsement, each trash, restore and removal of an entry, and each erasure marks what it touched. The marks are worked off at once, and what fails stays marked and is retried every `RETRY_EVERY` (30 seconds), with the full catch-up at start. A removal's `Removed` is written before its content is deleted, so the row goes first when the index is reachable. A search never returns an entry the state no longer has, so an entry trashed while the index is down is not found while its row waits for the retry. Trashing, restoring and sharing no longer fail or warn on the index; filing says when an entry cannot be searched yet.
