# The build box keeps its disk (2026-11-06)

- An installed-app session's temporary directory (TMPDIR) is inside its home, and ending a session waits until its process group has stopped (TERM, then KILL) before the home is removed. Reason: the update tests run the app as an AppImage with APPIMAGE_EXTRACT_AND_RUN, whose runtime unpacks itself into `$TMPDIR/appimage_extracted_<md5>` (about 260 MB) and removes that only when it exits on its own; the tests stop it, so 296 runs left 75 GB in /tmp and the build box filled (#203). Test: `desktop_app.rs` `an_appimage_a_test_stops_leaves_no_extraction_behind`.
- `release/ci-clean.sh` removes `appimage_extracted_*` directories in /tmp that are this user's, were unpacked three hours ago or more, and that no running process runs from or works in. Reason: extractions earlier runs left are still there, and one a person's app is running from must stay. Three hours is the age the script already uses for test realms, past any run's time limit. Test: `ci.rs` `appimage_extractions_left_for_three_hours_are_removed`.
- `release/ci-clean.sh` prunes the Docker build cache with `docker builder prune --all --filter until=10800s`, and leaves images alone. Reason: the build cache held 172 GB reclaimable and was never cleared; without `--all` only dangling records go, which left most of it. A build running now uses its cache, which is kept, and another run may be using an image. Test: `ci.rs` `docker_build_cache_unused_for_three_hours_is_pruned`.
- Every workflow (desktop, injection, appliance) checks for 25 GB free in its checkout and its temporary directory before it builds (`release/ci-disk.sh`, `MAGNUS_CI_FREE_GB`), and fails there saying how much is free and what a run needs; desktop checks after `ci-clean.sh` has freed what it can. Reason: with 1.3 GB free, Chromium crashed in four tests and the update test could not unpack its release, which read as broken tests. 25 GB is what a run can write: `target/` kept between runs measured 18 GB plus 2.7 GB for the desktop app on build-box on 2026-11-05, and a dependency or toolchain change writes all of it again; the installers, the update test's two AppImages (85 MB each) and their extractions and the screenshots add about 1 GB. Test: `ci.rs` `a_run_short_of_disk_fails_at_its_start_and_says_why`.
