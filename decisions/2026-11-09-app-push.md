# Connected apps push, and a push polls at once

The spec (Proactive › Triggers) says notifications from connected apps reach the server as events, by push where the service supports it and by polling where it does not, and each event wakes the agent. Polling existed (#369, #406); push did not.

**A push is a hint, not content.** `POST /v1/push/{app}/{person}/{token}` records `Ev::Push(Received)` and polls that app's watched reads at once, through the same polling run and `note_watched` diff as a scheduled poll. New items wake a review exactly as a poll's would. The body is read only for a subscription handshake (Microsoft Graph's `validationToken`, Slack's `url_verification`), so nothing an app or a forger sends reaches a model; the worst a stolen address does is cause extra reads. Reason: trusting a push's payload would put unreviewed outside text into the agent's context ahead of the boundary, and every provider shapes its payload differently, while every provider's push means the same thing: look now.

**The address is the credential.** Its token is an HMAC-SHA256 of the person and the app under `push_key`, a vault secret made on first use. No table, nothing stored per address; a wrong token answers 404. An app the person can no longer use (turned off, disconnected, lapsed, no watches) answers 410 so the app drops the subscription. Reason: secrets come from the vault only, and a derivable address needs no migration.

**Bursts poll once per 30 seconds** (`PUSH_MIN_GAP_SECS`). A push inside the gap stays pending and the sweep polls when the gap passes, so the last push of a burst is never lost. A push is recorded once until the poll that answers it starts, so a flood adds one event per poll, not per push. Pushes are poll marks' siblings: erasure drops them with the person.

**Push works for any app with a watched read**, with or without `poll_minutes`. Reason: push replaces the schedule for apps that support it; a watch with no schedule still wakes on push.

**Who registers the address.** The app's page shows Instant updates for watched apps, with Copy push address (copied, never shown, since it is a credential). Registering a subscription with each provider automatically needs per-provider connector code and is not built.

**Owner action.** `magnus.pyrallon.ai` requires a device certificate at the edge, which no provider presents. Pushes reach the server only once the Cloudflare client-certificate rule exempts the path prefix `/v1/push/` (docs/remote-access-and-relay.md, section 2).
