# Erasure drops baselines and marks (#412)

The `PersonErased` arm scrubbed person-keyed maps but not
`watched_seen`, `home_last_open`, `items_opened` or
`items_resolved_at`: whoever was next known by the erased name
inherited the old watched baselines (old items never waking),
the old home mark (feed starting mid-history) and orphan
opened/resolved timestamps. All four now go with the person,
beside the existing drops.

The opened marks are keyed by item id, not person, so the arm
collects the person's item ids first and retains against them —
the same collect-then-retain shape as attachments. No log change:
these maps rebuild from the log, and the person's watched ids were
already content-scrubbed (#410); this removes the state keys the
content scrub leaves behind.
