# 2026-11-22: Pure peer collaboration powered by each user's personal Magnus

## Decision
Shared projects are now pure peer collaboration spaces without a workspace Admin role hierarchy, Shared Computer VM, Shared Team Agent, Shared OAuth Apps, or Shared Spend limits:

1. **No workspace Admin ceremony:** Any regular (non-guest) authenticated user can start a shared project (`POST /v1/workspaces`) without needing a `Team Admin` server role grant. Any peer collaborator (`Member`) can view server people (`GET /v1/workspaces/{ws}/people`), add teammates (`POST /v1/workspaces/{ws}/members`, defaulting to `Role::Member`), invite by email or copy an invite link (`POST /v1/workspaces/{ws}/invites`), and create/manage their own routines (`POST/PATCH/DELETE /v1/workspaces/{ws}/routines`). Deleting a shared project for everyone (`DELETE /v1/workspaces/{ws}`) remains guarded to its creator (`Owner`), while any non-sole-owner collaborator can leave cleanly.
2. **Retire Shared Computer VM:** Creating a shared project no longer auto-provisions an `Owner::Workspace` VM (`crates/magnus/src/team/routes.rs`). Shared conversation headers stay bound to each collaborator's own personal computer chip because their personal Magnus uses their own computer.
3. **Each user's personal Magnus does their work and shares scrubbed outputs:** Mentioning `@Magnus` or asking in a shared conversation (`post_and_ask`) dispatches a `LaneKind::MemberAgent` Mission lane inside the requester's isolated personal agent boundary (`start_personal_room_mission`), honoring the composer's chosen model. Scrubbed outputs that satisfy the One-Sentence Rule auto-release and post inline into the shared conversation (`sender: "agent:<person>"`, preserving erasure ownership via `team::owner::person_of`); sensitive/credential-flagged or cross-user outputs hold privately in the owner's Release Airlock (`LaneDraftReady`) until reviewed and released.
4. **Simplified 2-card Project Settings:** Replaced split server-dropdown + email-form + role dropdowns + Shared Apps + Shared Spend + duplicate advertised-apps card with two cards: **People** (one unified `Name or email…` input with live 1-click suggestion chips, 1-click `Copy invite link`, and one merged peer roster displaying each collaborator's advertised personal apps) and **Danger zone** (`Leave` / creator-only `Delete project`). Admin › People › Shared projects shows a read-only overview of project names and counts without `Team Admin` toggle ceremony.
5. **Event-log rollback safety:** All historical event kinds (`Change::TeamAdmin`, `Change::Connector`, `Change::Run`, `Ev::Team`, etc.) retain their readers and replay cleanly.

## Reason
Once Magnus Teams unified into the single Magnus Stage + Bento + Canvas shell, maintaining a separate workspace Admin role, a shared computer VM, shared OAuth sign-ins, shared spend limits, and a separate shared Team Agent created administrative friction and dual-runtime complexity without improving collaboration. Running each user's work inside their own isolated personal Magnus — on their own computer, with their own personal apps and budget — and sharing only scrubbed outputs across the Release Airlock makes shared projects simpler, safer, and immediately usable by any teammate.
