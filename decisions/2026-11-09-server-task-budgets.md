# Budgets come from the server; reviews and wakes run on the per-task budget (2026-11-09)

The owner reported that Magnus had lost its autonomy. Tasks stopped on budget long before the server's limit, because their budget was what the model proposed. Spec rev 133 (Chat and tasks) says: "A task's budget defaults to the server's per-task limit. A model's cost estimate is shown to the person, never used as the cap." and "Reviews and other background wakes run on the per-task budget."

- **One place decides a task's budget.** That place is `task_budget.rs`. Every start goes through it: a proposal approved in chat or in the inbox, an accepted suggestion, a confirmed schedule's runs, a task under a grant, a proactive review and a watch poll. Each gets the server's `[budget]`. Under a grant, the dollars are also no more than what is left of the grant, which is the person's own figure.
- **A proposal's `estimated_cost_usd` is only shown.** It is still required and still checked against the server's limit. It no longer becomes `budget.max_usd`. The card now reads "About $X (estimated)" instead of "Up to $X". This supersedes the budget part of #254 (2026-11-06 task proposals).
- **The model cannot set a budget.** `create_schedule` and `suggest` no longer take a `budget`, and `card_budget` is gone. A card or schedule written before this change may still carry the model's figure. It is ignored when the card is approved, when the schedule fires and when the schedule is listed, so existing schedules get the server's limit as well. `ScheduleSet.budget` stays in the event for old readers, and new schedules write none.
- **"Handle things like this"** fills the grant form with the server's per-task limit. It used to fill four times the model's estimate.
- **Reviews and wakes.** A proactive review and a watch poll used to have small budgets of their own: $0.25 (`[proactive] wake_max_usd`) and 10 or 5 model calls. They now run on the per-task budget. Auto Review and the quality reviewer are charged to the run they review (`reviewer_call` emits `ReviewerReply`). Inside a review, that means the review's own budget, so a review no longer turns every boundary action into an ask because its tiny budget is spent. `wake_max_usd` is retired. Configs that still set it load, and the key is ignored.
- **Not changed.** A sub-agent still gets a share of its parent's budget (spec: "a share of the parent's budget"). "Double the budget" on a stopped run is still the person's choice. A grant's `max_usd` is still the person's to set.

Tests: `task_budget.rs` (an approved card and a stored schedule budget start the server's limit; no chat tool takes a budget; a grant lowers only the dollars), `suggestions.rs` `a_proposal_shows_the_estimate_and_starts_with_the_servers_budget`. In the scratch suites: `task_proposals.rs`, `proactive.rs` (the review's own budget is the server's), `chat.rs`, `schedules.rs` and `standing_authority.rs` now assert the server's limit.
