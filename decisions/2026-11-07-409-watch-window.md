# The watched baseline is a two-answer window (#409)

The #369 baseline accumulated every id ever seen, capped at five
thousand with arbitrary eviction past the cap. Any answer holding
more than the cap rewoke on every identical read: the evicted ids
looked new again. A cap on history cannot fix that — any cap has an
answer bigger than it — so the baseline is now the last two answers,
newest last, and the cap is gone.

Two answers bound the memory whatever the source holds (two inbox
pages, not all history), and an unchanged answer always diffs empty
against its own window, however many ids it carries — the property
the cap broke. The wake records the full answer's ids, not just the
fresh ones, because a window entry must be the whole answer to diff
against. The window still advances only when the wake starts a
review, so a dropped wake retries on the next read.

An item absent for one read stays known (still in the window); one
gone for two reads wakes again when it returns. That reappearance
wake is intended: after two reads away, the item is news again. Old
`WatchedSeen` events replay through the new arm unchanged — boot
replays the log, so no migration is needed.
