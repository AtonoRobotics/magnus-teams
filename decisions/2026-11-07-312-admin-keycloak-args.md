# The admin setup names Keycloak's admin origin from the config (2026-11-07)

- `release/admin-on-appliance.sh` passes `--admin-url`, `--admin-file` and `--ca` to `config/keycloak-client.py` explicitly: the origin and CA from `[sign_in.oidc] status_admin_url`/`status_admin_ca`, the admin file from `identity/admin.json` beside the config; with no identity configured it stops naming the missing setting (#312). Reason: the retired magnus-product deployment took its Keycloak and `/etc/magnus-production-origin/ca.pem` with it, so the client's defaults are dead and master desktop died in `ssl.create_default_context`; the box's live origin (19446) verifies against `status_admin_ca` (checked). This matches #292's required-args direction, and that PR touches the client script only, not this script. Test: `admin_on_appliance.rs` `the_setup_names_keycloaks_admin_origin_from_the_config_or_says_what_is_missing` (fails without, with the production traceback); the master desktop run itself is the positive gate.
