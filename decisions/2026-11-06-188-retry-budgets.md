# A retry is checked against the run as it is now (2026-11-06)

- Before every model request, the first and each retry alike, the loop reads the live run and stops without asking when it is no longer running (cancelled, suspended, ended), the kill switch is on, an update is under way, or its model calls or dollars are spent (`may_ask_model` in `run/agent_loop.rs`). Reason: a charged failure could cross `max_usd` and the loop, which checked only a model-call count, paid for more attempts; a cancel during the retry wait was retried anyway (#188). Tests: `a_charged_failure_past_the_dollar_limit_asks_the_model_no_more`, `a_task_cancelled_during_the_retry_wait_is_not_retried` (`tests/scratch/tests/model_retries.rs`).
- Each stop goes the way it already went: a cancelled or suspended run just stops, the kill switch and an update suspend it as the step does, and a spent budget suspends it with the `budget` notice, the dollar one worded by the boundary's budget stage (`boundary::budget_used`), so the person's "extend" doubles it as before. Reason: no new stop path; the same notice resumes the same way. Test: `a_charged_failure_past_the_dollar_limit_asks_the_model_no_more`.
- The action budget is not checked before a model call. Reason: a model request spends no action, and the boundary's budget stage already stops the first action past it. Test: none new (unchanged behaviour).
- The fake model can answer with a reply that is charged and names no model (`Reply::Charged`). Reason: through the real adapters that is the charged failure that reaches the loop (the adapter bills it, then fails it as malformed). Test: `a_charged_failure_past_the_dollar_limit_asks_the_model_no_more`.
