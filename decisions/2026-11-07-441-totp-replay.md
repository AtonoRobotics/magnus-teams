# TOTP steps are consumed on use (2026-11-07)

- A code signs in once: the last accepted step per person is recorded, and a code for a used or passed step rejects and counts like a wrong code (#441, from the #440 review). Reason: without it a captured password/code pair replays for the whole skew window, opening further sessions.
- Check-and-record happens under one lock with the step persisted beside the secrets (`totp-steps.json`). Reason: concurrent uses of one code must admit exactly one, and a restart must not resurrect a consumed step; the file mirrors `sessions.json` (mutex-guarded map, saved on mutation).
- `totp::verify_step` reports the matched step, lowest first, so a live code always names its own step; `verify` keeps its meaning on top. Reason: the sign-in layer needs the step to record it, and lowest-first keeps the report deterministic whatever the clock does mid-window.
