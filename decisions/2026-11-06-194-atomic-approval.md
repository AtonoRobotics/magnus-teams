# A decision on a card is one write (2026-11-06)

- `Kernel::respond` collects the card's resolution and everything it causes (an approval's grant, the waiting call's result, a contract, a policy, a schedule, a pin, an endorsement, a run's verification and end, and the run's `Resumed`) and writes them with one `emit_all`, the log's single-statement `append_all`. Separate writes let a crash leave a decided card with no grant, or a granted run that never resumed (#194). Tests: `a_crash_after_an_approval_is_decided_leaves_it_granted`, `a_crash_after_an_approval_is_granted_still_resumes_its_run`.
- The run's `Resumed` is in that write, so a restart needs no new recovery: a run the log shows running is driven again by the kernel's existing sweep, once, and the grant is used once. A crash before the write leaves the card open to decide again. Test: `a_crash_after_an_approval_is_granted_still_resumes_its_run`.
- A review accepted writes its resolution, verifications, result and `Completed` together, so a crash cannot leave an accepted review on a run that never ends. Test: `a_crash_after_a_review_is_accepted_still_completes_its_run`.
- The crash tests place the crash with a `crash-after` file in the state directory, which ends the process right after a write that logs the named event kind. It is compiled only with `debug_assertions`: the tests run debug builds and only release builds ship, so production has no such hook. A file, not an environment variable, so it fires once and the restart runs clean. Tests: all three in `tests/scratch/tests/approval_crash.rs`.
