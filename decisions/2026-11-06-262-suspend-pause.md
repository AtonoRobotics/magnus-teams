# Admin suspensions liftable only by admins; held schedules pausable (2026-11-06)

- An admin's suspension is marked by an `admin` flag on `SchedulePaused` plus `paused_by_admin` on the schedule, not by matching the reason string (#262). Reason: string-matching "Suspended by" is fragile; the additive `#[serde(default)]` field replays old log entries as unmarked, pinned by `state.rs` `an_admin_suspension_marks_the_schedule_until_resumed`. Only the admin path sets it.
- `resume_schedule` refuses a suspended schedule to non-admin, non-owner callers (409); admins and the owner may lift it through the person API too. Reason: "only by an admin" governs who, not which endpoint; the console path is unchanged.
- Pausing a held schedule converts the hold to a personal pause (`paused_on` cleared); the sweep hold/release arms are untouched. Reason: release keys on `paused_on`, so a converted pause is naturally kept when the hold ends; resuming while the run still waits re-holds within a tick through the existing hold arm, so no new logic was needed. A separate kept-pause flag was rejected as more invasive for the same outcome.
- `pause_schedule` refuses over an admin suspension for every caller, admins included. Reason: allowing it through the person API would overwrite the mark with a personal pause the person could then resume themselves — a downgrade hole. Admins change a suspension through the admin endpoint.
