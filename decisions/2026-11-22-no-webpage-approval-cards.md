# No webpage approval cards: redirect tainted Private web calls to research_web (OpenWeb)

**Choice.** In a tainted `Private` run (`private && untrusted`), constructed public URLs (`web_fetch`, `browser_navigate`) and public browser interactions (`browser_click`, `browser_type`) are never sent to a `NEW_DESTINATION` webpage approval card (`UrlVerdict::Ask` is removed). Instead they are silently denied and redirected to `research_web`, which runs in an isolated `OpenWeb` worker (`private == false`) with full autonomous search, page fetch, and browser navigation/clicking. `harness_text` now directs the agent to prefer `research_web` for public web research and browsing.

**Reason.** After `decisions/2026-11-22-a-classifier-clear-is-not-a-pass.md` removed `UrlVerdict::Allow`, `fallback_url_verdict` fell back to `UrlVerdict::Ask` for queryless `web_fetch` and all `browser_navigate`, and `harness_text` still steered the main `Private` run to call `web_search`/`web_fetch`/`browser_*` directly. That caused the user to be prompted to approve every webpage. Redirecting to `research_web` preserves the Rule of Two strictly (never resting on a model classifier) while eliminating webpage approval prompts completely because `OpenWeb` holds zero private data.
