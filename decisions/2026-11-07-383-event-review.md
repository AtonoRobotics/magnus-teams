# Event reviews see the ended task (#383)

Codex P1 on #370: an event review got only `task done` / `task failed`
and the unfinished-work section excludes ended tasks, so a
failure-triggered review could not identify what failed.

The wake now carries the ended task's ID and outcome. The reason names
the task (`task {id} done|failed`, following the schedule/commitment/
approval reason shapes, parsed for wake marks the same way), and the
review's context opens with the task and its outcome line (failure
reason or completion summary, both of which land in the run summary).
The ID also renders in the review's title line.

The wake dedup changed with it: the five-minute any-review window
silently dropped failures after a cadence review or a boot, and made
the path untestable. Event wakes now dedup per task with a wake mark (a
task ends once), keeping the already-going check. A wake during an
active review is still dropped with no retry; that backstop is #386.
