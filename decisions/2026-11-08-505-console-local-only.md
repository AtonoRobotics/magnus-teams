# The console signs in only against the local store (2026-11-08, #505 slice A)

- The console's OIDC sign-in is deleted: `/auth/login`, `/auth/callback`, `/auth/step-up` routes, the `verify`/`check_claims`/roles/`Pending` machinery in `admin/auth.rs`, and the IdP health probe in `admin/ops.rs` (#505, slice A of the #429 retirement). Reason: Keycloak was to be retired and the integrated login is the only login (owner); the provider page was still authenticating admins. The console's Sign in opens its own form (`/auth/local`); a step-up re-asks the password there (`/auth/local/step-up`).
- What stays for later slices: the Users directory still reads the realm (slice B), the kernel's own provider sign-in (`/v1/sign-in/device`, `/v1/sign-in/browser`, `k.oidc`) still serves the desktop app, and `issuer` is still required config. Deleting those is separate work under #429, sequenced after this lands.
- A refused local sign-in is audited as `sign_in_refused`, as a provider refusal was. Reason: the sign-in test's contract ("every one of those is in the audit log") rests on it; a lost entry must not open the door, so the audit failure only logs.
- The `session_ended_by_provider` audit action is `session_ended`: the guard re-checks standing at the kernel (`/v1/admin/console-standing`), not the provider. Turning an admin off at the appliance ends their console session at the next refresh; re-enabling never revives it.
- There is no silent entry anymore: nothing remembers the browser, so signing in again asks for the password anew, and (unlike a provider passthrough) counts as a step-up. The `MAGNUS_AGAIN` browser step now asserts the password is asked, and the repurposed test asserts `stepped_up_until` is set.
- The OIDC `state`/`nonce` replay test is replaced by the login-binding test: the form's token works only with its cookie, and the first submission spends it whether the password was right or wrong.
- Tests: `admin_sign_in.rs` rewritten local-only (9/9: 4 browser incl. the full session-rules flow, 5 sync); the other nine console suites converted to `local_user` + password sign-in, keeping their Keycloak directory fixtures (`admin_shell` verified green with the realm attached, 31s; the rest run in CI). New `local_user`/`set_status` helpers shell to `person-add`/`person-role`/`person-status` with lowercase ids (#470).
