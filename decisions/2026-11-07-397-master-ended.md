# Stale-green merges break master; the master run catches them (#397)

#392's checks passed on a merge ref computed before #391 merged, and
GitHub merged the branch without recompiling against current master,
so master went red (E0308: tuple `Ended` vs struct `Ended`). This is
the failure mode rule 3 accepts by design: PR checks may be stale,
and the post-merge master run is the gate that catches it.

No process change: branch protection cannot require fresh checks
without re-running every open PR on each merge (the shared-runner
meltdown rule 3 already avoids). The fix is the one-line type
annotation; the existing proactive suite covers the code path, it
just could not run.
