# Scheduled polling for watched apps (#406)

Digest v1 (#369) diffs watched answers only when runs happen to
read them: items that arrive and are never read again never wake,
and a wake dropped for an active review retries only on the next
read. Each watch gains an optional `poll_minutes`; the sweep starts
one minimal polling run per due watch, and its answer flows through
the same `note_watched` hook as any read — no separate diff path.

A poll is a run with actor `poll`: one tool call, then end, on a
budget of 3 model calls, 1 action, and the wake's usd cap. Its task
carries a `poll` flag mirroring `review`: it ends contract-free,
never fast-wakes or backstop-wakes a review on ending, stays out of
the review's unfinished-work context, and hides from the person's
task list, search and home feed — polls fire dozens a day, so they
hide further than reviews, staying auditable by task id and in the
log. Polls run even while a review is active and are not loop-
governed: a plain read waits for nothing and needs no leave.

Due means never polled, or the interval passed since the last poll
started (`Ev::WatchPolled`, event-sourced like everything else, so
no migration). The clock restarts at start, not at answer; a failed
start stays due and retries next sweep. A task read does not reset
the poll clock in v1 — coalescing reads and polls is #413. Erasure
drops poll clocks with the person.
