# Policy evaluation grows its own stack (#375)

Cedar refuses to evaluate with less than 100KB of remaining stack, and
reports it as a policy `recursion limit` error
(`cedar-policy-core/.../evaluator.rs`: `REQUIRED_STACK_SPACE`, checked at
every expression node). The boundary fails closed, so a deep caller turns
into denied reads: the verifier's `mail__list_sent` on #370's merge ref,
suspending the run on budget.

Measured in debug builds: an evaluation itself takes hundreds of KB (a
3-term constraint trips with 400KB remaining at entry), and the overflow
edge sits near 190KB. The verifier's poll chain was within a few KB of
the floor; #237's run frames plus #372's boundary frames together tipped
it over, while each side alone fits.

The fix wraps the single evaluation site (`policy::eval`, used for tool
calls, controls and grants alike) in `stacker::grow(2MB)`. Two megabytes
covers deep real-world policies over the measured usage with margin; the
segment allocates only when the stack is short, so a shallow call pays
one pointer check. `stacker 0.1` was already in the lock file via Cedar,
so the dependency adds no new supply chain.

Alternatives: boxing caller frames (what #370 does) only moves the edge
and breaks again on the next growth; a dedicated evaluation thread costs
a spawn per layer per action. Growing at the eval is the systemic fix the
issue asks for.
