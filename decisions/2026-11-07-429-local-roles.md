# Local roles guard the last admin (2026-11-07)

- #429 slice 3 is the local console role: admin or member per person in `roles.json`, unrecorded is a member, set by CLI, read fresh. Reason: console login on the local store (the next slice) needs a local answer to "is this an admin", and the Users slice needs role changes; both build on this store.
- The role axis is admin/member for console entry, separate from the kernel's owner/developer roles. Reason: conflating them would rewire every kernel role check; the console's admin question is genuinely a different one (today it comes from the realm, not the kernel at all).
- Demoting or disabling the last enabled admin refuses, with the console's own message; only enabled (active) admins count, and an unmanaged switch never guards. Reason: the organisation must never strand itself with nobody able to administer, while an appliance that never assigned roles keeps working exactly as before.
- The `invites` mutex widened to `people`, covering roles and statuses too. Reason: concurrent switches must not interleave past the guard; one lock over all local-people mutations keeps check-and-set atomic.
