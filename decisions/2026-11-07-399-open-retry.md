# Opened-reporting retries after failure (#399)

Codex P2 on #396: presented ids joined `App.reported` before the
`POST /v1/inbox/opened` request completed, so a transient failure
left seen observations with null `opened_at` for the session.

An id now counts as reported only on success; on failure it leaves
the in-flight set unmarked, so the next refresh retries. In-flight
ids are held aside so overlapping refreshes do not report twice
(the endpoint is idempotent anyway; this saves the request).

Verified with a throwaway node probe (`/tmp/openretry-probe.mjs`,
kept out of the repo) that executes the shipped block against a
fail-then-succeed stub: old code marks despite failure, new code
retries and marks once in exactly two calls. No maintained test:
the repo has no JS unit harness (webdriver flows only, unrunnable
here), and the failure mode needs fault injection the flows lack.
