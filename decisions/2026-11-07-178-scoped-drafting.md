# Scoped drafting: drafts are rewritten where B cannot reach (2026-11-07)

- A draft write (`create/reply/forward/update_draft`, by remote tool name on any connector) runs as a scoped step (#178, CaMeL narrowly applied): after the gate allows it, the kernel builds a fresh context — the target thread (read by the kernel through the person's sign-in) plus the person's own words (their task text and chat messages) — and a model call with no tools writes the body. The run's own body is discarded, not shown: anything in it from another thread would break the sources claim. Headers (to/subject) still come from the run's input.
- The kernel records the draft's sources from that context: `Ev::DraftScoped { draft, threads, participants }`, where participants are the threads' From/To/Cc/Bcc addresses. A create records no threads. An update keeps the draft's recorded sources, or none when it has none (a person's own or pre-feature draft: fail closed, the send asks as today). State keeps `draft_sources` for the gate.
- Content provenance at the send gate: a send whose draft has recorded non-empty sources, every recipient a participant of them, passes the Rule-of-Two and audience taint asks (policy asks stand, as with recipient provenance). Rationale: the content provably came only from those threads, and every recipient already holds them — nothing new is disclosed, and injected threads never entered the writing context. Empty sources (a create) waive nothing: the recipients are still the tainted run's choice.
- A spent budget or failed scoped call falls back to the run's body with no sources recorded: today's behavior (the send asks), never a denied draft or a forged claim. The scoped call counts against the run's budget like the verifier's.
- `update_draft`'s existing text reaches the scoped step as the current draft: trusted when sources are recorded (it is grounded in them), untrusted suggestion otherwise (grounded in the person's request only).
