# 2026-11-23 — Rich Agent Findings, Concurrent Execution, Dynamic Bento, Sidebar Tabs, and Task/Schedule Deletion

## Context
Users observed six compounding regressions in day-to-day autonomous work:
1. Sub-agents, chat transcripts, `get_task`, and team lanes discarded composed deliverables (`outcome_view`), delivered files, and evidence, returning only thin one-line summaries while instructions drifted away from concrete end-user findings.
2. Consecutive `start_sub_agent` / `research_web` calls executed serially in `Kernel::step`, `start_sub_agent` always blocked the parent until completion, and `Sandboxes::vm` held a global lock across Firecracker VM boot—tying up the main agent and blocking concurrent autonomous work.
3. Approval cards, inline results, sub-agent rows, evidence receipts, and chat task cards hid critical context behind closed `<details>` blocks or `.chatcard .rg-main .sub { display: none; }`.
4. Aurora bento boxes auto-expired running tasks after 15 seconds, ignored concurrent tasks outside the current thread, suppressed approvals when auto-opening the panel, and churned DOM nodes without dynamic recency reordering.
5. The right sidebar lacked top-bar tabs for Tasks and Routines (and Aurora's canvas rendered no top-bar tab strip at all).
6. Active/paused schedules and the Heartbeat card had no Delete control, and deleting a task closed the right sidebar instead of returning to the Tasks list.

## Decisions
- **Preserve full findings end-to-end:** Render composed deliverables (`render_deliverable` in `crates/magnus/src/sub_agents.rs`) and attach delivered files, action receipts, and sources across sub-agent results, chat `Result` transcript/text entries, `get_task`, and team lanes. Strengthen `chat.md`, `agent.md`, and OpenWeb research prompts to surface concrete facts, numbers, tables, visuals, and citations in plain user-facing language without exposing internal tool mechanics.
- **Enable true parallel & background work:** Execute consecutive `start_sub_agent`/`research_web` tool calls concurrently via `futures::future::join_all` in `Kernel::step`, add an optional `background: bool` flag to `start_sub_agent` (pinned in `tool_specs.snapshot.json`), and replace the global `Sandboxes::vm` boot mutex with per-run boot locks.
- **Surface rich details upfront across cards & evidence:** Remove `.chatcard .rg-main .sub { display: none; }`, render structured `.ask-preview` fields directly on approval cards (still hiding all policy/rule/taint internals per spec rev 140), open completed inline results and sub-agent findings by default, make sub-agents clickable links to `task:<id>` with live `status_line` and file chips, show receipt `to` destinations, inline read-back summaries, full source attribution, and `not_done` tools in `evidence.js`, and expose `has_deliverable`, `receipts_count`, `verified`, and `sub_agents_active` on `GET /v1/tasks`.
- **Make Aurora bento boxes genuinely dynamic (superseding `2026-11-21-aurora-boxes-come-and-go.md` for running work):** Keep active `tone: "run"` tiles pinned while executing, extend passive tile visibility to 90s with content-change resurfacing, surface concurrent autonomous tasks across threads and up to 2 approval tiles with previews + 1-tap actions, dynamically sort tiles by urgency + recency (`touchedAt`), avoid gratuitous DOM re-appends, run FLIP `slide()` before `grow()`, and avoid auto-opening the `"needs"` panel in Aurora stage mode.
- **Unify right-sidebar top-bar tabs:** Display `Activity`, `Tasks` (with active count badge), `Routines`, `Approvals` (with pending badge), `Files`, and `Apps` in the right sidebar's top bar across both standard (`SidePanel.shell`) and Aurora (`AuroraStage.shell`) themes.
- **Fix schedule and multi-task deletion:** Add `Delete` actions to active, paused, ended, Heartbeat, and Activity schedule cards, return to `"schedules"` when deleting `schedule:<id>`, keep the right sidebar open on `"tasks"` when deleting `task:<id>`, and add inline trash buttons on ended rows in `tasksView()`.
