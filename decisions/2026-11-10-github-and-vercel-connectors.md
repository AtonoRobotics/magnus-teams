# GitHub and Vercel catalog connectors, on the owner's clients

**Choice.** `catalog/github.toml` and `catalog/vercel.toml` are remote connectors with `registration = "preregistered"`, signing in with the clients in `catalog/registrations.toml` (`github`: confidential, "AtonoRobotics OAuth app"; `vercel`: public, "Magnus by Alpha Vector"), whose IDs, and GitHub's secret, the release provisions (`decisions/2026-11-10-provisioned-client-ids.md`).

- GitHub: `https://api.githubcopilot.com/mcp/`, the remote GitHub MCP server's default toolsets (context, repos, issues, pull_requests, users) plus the copilot toolset, 48 tools: 27 read, 6 reversible_write, 12 irreversible, 3 financial. The opt-in toolsets stay hidden. Scopes `repo` and `read:org`; `workflow` and `delete_repo` come through the server's scope challenge when a call needs them. No fixed redirect: an OAuth app whose callback is `http://127.0.0.1/callback` takes any loopback port.
- Vercel: `https://mcp.vercel.com/`, 263 tools (Vercel's tool reference plus what the server lists to a signed-in client): 158 read, 24 reversible_write, 69 irreversible, 12 financial. Scopes `openid` (the only one its metadata offers) and `offline_access`. A fixed redirect, `http://127.0.0.1:17321/callback`, the port the desktop already listens on for Slack, because Vercel matches the callback exactly.
- The classes follow the house rule and take the stricter class when unsure. Commits (they can land on a deploying branch and stay in history), new issues, comments, pull requests and reviews (people are notified), deploys, promotions, rollbacks, pausing, domains, DNS, certificates, environment variables, keys and tokens, protection, the firewall, live routing, feature flags and Global Config items, log drains and team authorisation are irreversible. Reading a decrypted environment variable is irreversible, because the secret cannot be unread. Buying domains, sandboxes, Vercel CI and check reruns, and Copilot's agent and review are financial.
- The token exchange and refresh now send `Accept: application/json` (`crates/magnus/src/token_endpoint.rs`). GitHub's token endpoint otherwise answers form-encoded, and the JSON parse refused every GitHub sign-in.

**Reason.** The owner chose to build these connectors on the clients already registered. Both servers were probed on 2026-11-10. GitHub's protected-resource metadata names `https://github.com/login/oauth`, which offers PKCE and no dynamic registration, so the only way in is a registered client. Vercel's names `https://vercel.com`, which takes only reviewed clients or Client ID Metadata Documents for MCP.

**What works when.** GitHub works after the next release, provided the OAuth app's callback is `http://127.0.0.1/callback`. That is the address `docs/remote-access-and-relay.md` keeps it on until the relay cutover, and it can only be checked signed in. An organisation that restricts OAuth apps needs an owner's approval of the app first. Vercel needs two owner steps: Vercel approving "Magnus by Alpha Vector" for Vercel MCP (its allowlist), and `http://127.0.0.1:17321/callback` registered as the app's callback. Until both are done, its sign-in fails at Vercel. At the relay cutover, both move to `https://pyrallon.ai/v1/connections/callback` with the other confidential clients, and Vercel's `redirect_uri` changes with them. A Client ID Metadata Document would avoid Vercel's review altogether, but it needs an https address Alpha Vector serves, which does not exist yet.
