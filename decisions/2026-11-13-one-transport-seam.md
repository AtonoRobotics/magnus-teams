# One transport seam: a connector's calls go through `Transport`, never a string compare

**Choice.** `transport.rs` parses a connector's `transport` string once into `transport::Kind` (`McpHttp`, `Brokered`), and the kernel hands out a `Transport` for a connector (`Kernel::transport(c)`), an enum over the two adapters that exist (`apps::Mcp`, `brokered::Brokered`) plus a `#[cfg(test)]` `Fake`. It owns what differs between them: `tools(bearer)`, `call(person, bearer, tool, args, fence, key)`, `kind()` (whose `definitions_fixed()` and `signs_in_at_provider()` are the brokered rules), and `view_of`/`read_view` (only a remote app has views). The seven `c.transport == BROKERED` branches are gone: the two boundary paths (`connector_call`, the connector arm of `call`), `app_tools` (moved here from `brokered.rs`), the pin rule in `tool_gate.rs`, the sign-in target that `connectors.rs` and `connectors/relay/sign_in.rs` each copied (now `connectors/sign_in_target.rs`, one function), and the config check. The literals `"mcp_http"`/`"brokered"` in `catalog.rs`, `generated.rs` and `connectors.rs` are the constants `transport::MCP_HTTP`/`BROKERED`; the wire and config strings are unchanged and the `Connector.transport` field stays a string, so no event reader changes.

**One call path, the fence and key chosen by the caller.** Both boundary paths now call `self.transport(c).call(...)`. The difference between them was not a bug, so each keeps its own:
- An agent's call (`call`): fence = `may_send` (no stop since its token, kill switch off, still signed in) and `still_running` (the run, read live); key = the action's idempotency key when the app takes `idempotency = "header"`. `still_running` is also checked just before, as before.
- The gate's and the identity tool's reads (`connector_call`): fence = `may_send` only, since a gate read has no run of its own to be still running; key = none, since a read changes nothing to deduplicate.

The fence is checked by a brokered call once it has its microVM and before it sends; a remote MCP call has no such wait, so it does not run the fence, and the caller's own checks just before it are its fence, as before. Running `may_send` for a remote app would refuse one with no credential configured for a person "not signed in", so it is not added.

**One behaviour change: an unknown `transport` stops the server at startup.** Before, any string other than `"brokered"` (a typo, `"mcp_stdio"`) was silently taken for a remote MCP app. The config is typed and validated at startup (Code Standard), so `Config::load` now refuses it: `connector <name>: unknown transport <value>`. No shipped or documented config names another value. A connector read from the log (catalog installs, generated connectors, the owner's own) was written by the server with one of the two names; one with any other still reads as a remote app (`Connector::kind`), as it did, so no older event becomes unreadable.

**Tests without a microVM or an app server.** `transport::fake::Fake` is installed under a fresh `fake://` url and records what it is sent; it checks the fence as a brokered call does and can hold a call before its fence, as a microVM's boot does. `boundary_transport_tests.rs` uses it against a booted kernel: an agent's call carries its key only to an app that takes one; a run cancelled while its call waits sends nothing; a gate read is fenced by the kill switch with no run and carries no key; a schema-breaking answer is unusable for a read and unknown for a write.
