# get_task and get_schedule read one by id (2026-11-07)

- New `get_task` / `get_schedule` conversation tools return one task or schedule by id: the list's row (status, result or latest run, what it did), however old, under the same who-may-control rule — someone else's, and a missing id, both read "no such task/schedule" so existence is not told (#265). Reason: Magnus had only the newest-30 list, so it could not look at an older task at all. The row builders are shared with the lists, so the two cannot disagree. Read policy (redaction, read recording) and summary taint apply as for lists. Tests: `magnus_gets_one_task_or_schedule_in_conversation` (fails without: unknown tool), `getting_a_tainted_task_taints_the_turn_that_reads_it` (fails without: the turn stays clean and sends the summary out), `get_reaches_any_controlled_task_or_schedule` (fails without: no lookup; pins the oldest of 31 with its result, and the owner/other gating).
