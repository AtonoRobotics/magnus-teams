# Grow the policy stack only when short (#377)

Codex P2 on #376, confirmed against the stacker 0.1.25 source: `grow`
always allocates a new stack, so every policy evaluation paid a 2MB
segment even for shallow callers. The eval now uses `maybe_grow` with a
1MB red zone over a 2MB segment: callers with room run inline exactly as
before (no behavior change possible there), and only deep callers move.
1MB is over twice the measured evaluation need (~400KB in debug for a
small policy), so the inline path keeps its margin.
