# An admin's task-item read never returns relationship notes (2026-11-06)

- An admin's item read of a chat turn is refused (404), as the tasks list already leaves turns out: the item read filtered only by person, so a turn's id returned `timeline_of` with every tool call's input and result, and a `relationship_note` result lists the person's whole notes (`person_admin.rs`). Reason: a chat turn is not a task; the mismatch was the leak. Test: `relationship_memory.rs` `an_admins_item_read_refuses_a_chat_turn_and_hides_notes_in_task_timelines` (fails on the old code: the read answered 200).
- The calls that are the person's alone (`relationship_note`, `disagreement`; `tools::person_only_tool`) keep their name but lose their words in every read served to anyone but the run's person: the admin's task timeline, the developer view's run inspector, and the raw log (which joins the content store through the kernel role, past the person's wall). Refusing chat turns alone would not do: a clean task can record a note too, and even a refused call's input carries its words. The disagreement record and outcome events lose their words the same way. The person's own timeline is unchanged. Reason: the spec's "never surfaces to another user" is absolute, unlike memory's recorded-read path. Tests: the same (a task's note hidden from the admin, shown to its person; fails on the old code) and `a_developer_reading_another_persons_run_sees_no_note_or_disagreement_words` (inspector and raw log; fails on the old code, which showed the note list and the disagreement's position and decision).
