# A file under /workspace is opened beneath it, and the CI gates fail closed

**Choice.** The guest agent opens every path under `/workspace` with openat2(2) and `RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS`, relative to a descriptor for `/workspace` (`sandbox/guest/src/files.rs`). That covers `read`, `write` (each missing parent folder is made with `mkdirat` in a parent opened the same way), `list` (the directory is opened beneath, and each entry's metadata is its own, links not followed) and `erase` (opened beneath with `O_NOFOLLOW`, then `unlinkat` in a parent opened beneath). A link that stays inside the area is followed; one that leads out of it, an absolute link (even to somewhere inside), or `..` past the top is refused with "leads out of /workspace". Paths elsewhere in the guest (the kernel's CA file, a screenshot, an installer) keep plain resolution: only the kernel names them.

**Reason.** The kernel's `user_path` checks a string prefix, and the guest followed links, so `/workspace/link -> /etc` let a person's or an operator's read, write, listing or erase reach the whole guest, breaking the promise that an operator session reaches the user's files and nothing else (`computer/takeover.rs`, `operator_file`). Only the guest can resolve a path against its own filesystem, and openat2 checks the whole resolution in the kernel at once, so a link swapped in while a request runs cannot pass a check made before it. The guest kernel is 6.1; openat2 is in Linux since 5.6. Refusing absolute links inside the area is the safer reading: telling one that stays inside from one that leaves would mean resolving links ourselves, which is the race this replaces.

**Choice.** `ci/ratchet.sh clippy` fails unless cargo exits 0 and its JSON holds a successful `build-finished`: no output, garbage, a missing toolchain or an unfinished build is a failure, never zero warnings. A warning without a place in the code now counts, once per text (rustc's "N warnings emitted" summary excepted). There were none: the count on Strix Beta is 686 either way, and the baseline is lowered from 694 to 686. `ci/ratchet-check.sh` (in the fast tier) checks this with a stand-in cargo.

**Choice.** `ci/ratchet.sh size` covers new files not yet added (`git ls-files --others --exclude-standard`), and each baseline in `ci/oversize.txt` is the file's current length: a file that shrinks has its baseline lowered in the same change, and one back under 800 lines leaves the list. The bases are lowered to today's lengths; `chat.rs`, `log.rs` and `tests/scratch/tests/chat.rs` leave it.

**Reason.** A baseline above the current length let a file grow back by the difference (`run/mod.rs` had 311 lines of room), and an empty or broken clippy run passed as zero warnings.

**Choice.** `ci/production-guard.sh` splits the command, minding quotes, into the simple commands it runs, and only a command whose program is `ci/on-strix-beta.sh` is let through for being sent to Strix. Quoted words are never read as commands (a commit message can say "cargo test"), except text a shell runs here: the argument of `sh -c`/`bash -c`, a here-document fed to a shell, and `$(...)` or a backquote inside double quotes, each checked the same way. `ci/production-guard-check.sh` covers `cargo test # ci/on-strix-beta.sh`, `sh -c 'cargo test'`, `bash -c "cargo build"`, a local `cargo build` chained after a Strix run, and legitimate commands (git, `cargo fmt`, `ci/ratchet.sh size`, Strix runs piped to `tail`, commit messages through a here-document).

**Reason.** The old guard let any command that mentioned `on-strix-beta.sh` anywhere through, and did not look inside `-c` strings. It is a seatbelt, not a sandbox: `eval`, `xargs`, `make` or a script still get past it.

**Not done here.** The live hook is the copy at `~/.claude/hooks/production-guard.sh` (`~/.claude/settings.json`); it is replaced with this file when the owner copies it there.
