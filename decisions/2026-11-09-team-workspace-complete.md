# The team workspace is finished to the spec

Sub-agents in a thread inherit its scope, and a tainted parent's child starts tainted, because what the parent read travels in the goal it writes. Working notes end with their task. Each project has its own knowledge base, read only by its people, including over a workspace admin. Admins name approvers per resource, and those named are the only ones who can answer. The team computer takes no run that has read private data.

Team content is listed as event content, so deleting an entry or a workspace removes the words from the log and scrubs the backups. Before this, deleting them left the text in the event log for good. Team files are now in the backups, and a deleted workspace's files age out with those backups, within the purge window.

A team routine runs in the background and asks no one, so standing work cannot do what would need a person. The first run is at once, so the admin who set it sees its report.

Reason: the spec's rules for each of these, and a retired `fact` event keeps its reader as a workspace-level entry.
