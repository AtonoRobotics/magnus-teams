# A card answers the wait it was made for

**Choice.**
- An answer to a card lets its run go on only while the run is stopped waiting on that card (`inbox::waits_on`, used by `Kernel::resume_on`): the card the run stopped on or, for a stop that names no card (a sign-in, a takeover asked for, a held reply met again), a card of the kind it stopped for. A run that went on since and now waits on something else (a timer, another card) stays where it is. The answer is still recorded and, for an ask, still grants and tells the run.
- An unattended ask that expires lets its run go on on purpose, through the same check: `due` already requires that the run waits on it. A later answer to the card that stays open tells the run but resumes nothing.
- "More budget" on a stop notice applies only while the run is stopped on that notice; otherwise it is refused with a conflict and the notice stays open. "Continue" on such a notice puts it away and resumes nothing.
- A run's end (its first Completed, Failed or Cancelled) closes, in the fold, every open card of the run it could wait on to go on (`WAITS_OF_A_RUN`: approval, question, review, monitor, secure form, takeover request, contract change) and the notice it was stopped on. They are resolved `superseded` by the kernel, the word retired cards already use, with the text "The task this was for has ended". Its outputs (suggestions, messages, drafts) and other notices stay. `respond` refuses a closed card, or a waiting card of an ended run, with a conflict. It holds on replay because it is the fold.
- The first answer to a card wins: `ItemResolved` on a card already resolved changes nothing in the fold. The three places that resolve cards outside `respond` (a filled secure form, a handback, a Link payment's cards) take the decide lock and read what is still open before writing. So does the task's Resume, so an answer and a Resume never both act on one stop.

**Reason.** `resume` resumed a suspended run whatever it waited on. A scheduled run whose ask had expired went on, stopped until 09:00 the next day, and a late answer to the old card woke it at once. A budget notice's "more budget" doubled the budget of a run already resumed. Cards of ended runs stayed answerable: Allow always wrote a standing rule from a dead run's card, and a question's answer was appended to a run that had ended. Three paths overwrote a card's resolution without checking it was still open.
