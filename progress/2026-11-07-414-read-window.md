`note_watched` now records no-news answers in the window too, so it
holds the last two reads; dropped wakes still record nothing and
retry. One-line behavior change plus doc updates; the #409 field doc
("last two answers") already says reads.

`{a},{b},{a},{c},{a}` all silent, then `{b},{c},{a}` wakes on the
return after two consecutive absences. New
`two_empty_reads_forget_then_reappearance_wakes` pins the reported
empty-answer case. Both failed before (spurious wake; 60s timeout),
all 4 new_items pass after. Gate: proactive 9, reviewer 6, lib 116,
inv4 11, inv7 5, workspace check clean.

Gotcha (second time): the appliance binary is the
`magnus-invariants` package (`tests/invariants/src/bin/`), not
`-p magnus`. `cargo build -p magnus --bins` builds `magnus` and
`magnus-admin` and leaves the appliance stale — silently, with a
fresh mtime on the wrong files. Always build
`-p magnus-invariants -p magnus --bins` before scratch tests.
