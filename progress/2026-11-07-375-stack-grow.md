# Policy evaluation grows its own stack (#375)

## What changed

- `crates/magnus/src/policy.rs`: `eval()` runs parse plus authorization
  inside `stacker::grow(2MB)`, so every Cedar decision is independent of
  its caller's stack depth. Added the regression test
  `a_decision_deep_in_the_stack_still_evaluates`: it burns the test
  thread's stack into a calibrated band ([200KB, 260KB] remaining,
  asserted) and decides a read. Without the grow it fails with the exact
  production error (`recursion limit reached`); with it, it allows.
- `crates/magnus/Cargo.toml` + `Cargo.lock`: direct `stacker 0.1`
  dependency (already locked via Cedar; the lock gains one edge).

## Why now

#370's CI merge ref fails in the modules suite: the verifier's reads are
denied by Cedar's recursion-limit because #237's frames plus #372's
frames together exceed the remaining-stack floor. Each side alone fits,
so neither side's own suite catches it. This fix unblocks #370: its merge
ref will evaluate cleanly however deep the path grows.

## Verification

- New test red without the fix (exact production error), green with it.
- Full `magnus` lib suite: 112 passed.
- `magnus-scratch --test modules`: 3 passed.
- Merge of the proactive branch plus master plus this fix: the verifier
  ablation passes (validated before pushing).
