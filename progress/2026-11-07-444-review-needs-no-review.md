# A review that decides nothing completes quietly (2026-11-07)

- `run/mod.rs` `task_complete`: a review or poll that started no work completes without a contract check, even when it recorded one. Seen by the owner on task `task_604aa80fb2f84121822cc4dd32ec489c`.
- Test: new `a_review_that_decides_nothing_needs_no_review_whatever_its_contract` in `tests/scratch/tests/proactive.rs`; it fails without the change (the review suspends on a `review` item and never completes) and passed 5 of 5 runs with it.
- Found while testing, not fixed here: outside 09:00 to 17:00 UTC a review starts at boot and can reach the model before the harness stores the provider key. It pauses on the sign-in notice, and a paused review holds every later review for that person. The proactive tests that trigger their own review then time out; on unchanged master `review_observes_and_the_person_sees_it` failed 2 of 3 runs at 18:50 UTC. The new test resumes that paused review first. The same hold applies in the product when a model sign-in expires during a review.
- Background containment: `kernel.rs` `suspend_on` fails a background run instead of suspending it, and `settle_background` (in the sweep) ends background runs and cards left waiting; `boundary.rs` refuses a background run's approval and reviewer-flag asks with a reason it can act on; `run/mod.rs` completes a background run with unchecked criteria and sends no failure notice; `api.rs` kill-switch release fails background runs quietly; `state.rs` adds `Task::background` and `BACKGROUND_OUTPUTS`; `controls.rs` and `desktop/ui/app.js` drop background tasks from the person's lists.
- Tests: new `a_review_that_would_need_approval_is_refused_and_asks_no_one` and `a_review_stopped_by_its_budget_ends_quietly_and_reviews_go_on`; both pass with the change on a rebuilt `magnus-appliance`. The harness runs `magnus-appliance` (package `magnus-invariants`), so `cargo build -p magnus` alone tests a stale binary. The boot-review race above no longer holds later reviews: the overnight review that hits the missing key now fails quietly.
- Review fix (Codex on #446): `BACKGROUND_OUTPUTS` now keeps `interrupt`, so the sweep no longer dismisses a review's interruption within half a second. Test: new `a_review_interruption_stays_open_after_the_sweep`, which fails without it.
